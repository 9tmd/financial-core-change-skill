# 财务内核改动纪律

多租户财务系统「钱相关的核心」改动清单。最高准则一句话：**钱不能凭空多/少。**

## 何时用

改动触及余额、派奖/结算、资金流转、迁移、回退、或写保护财务表时。

## 1. 单写者区

财务内核、数据库迁移、版本号是单写者区——同一时间只许一个会话碰。要并行就把前端视图/报表/测试/只读调研拆出去，这三个区绝不并行。

## 2. 镜像检查器（最容易漏、最致命）

运行时写路径改了，纯函数检查器必须同步镜像，否则对拍漂移：

- 运行时写路径 ↔ 纯函数检查器（forward/reverse 成对：apply/undo、carry/un-carry）
- 重放、守恒、重算路径与运行时同口径

「只改写路径、不改检查器」的提交是硬伤。

## 3. 守恒恒等式

改动触及服务费/派奖/回退/余额边界时，逐行核对并确认守恒恒等式成立（如 `费用总额 == Σ各分成`）。两套账勿混：写快照的服务费链 vs 读重算的流水账（派奖后锁）。

## 4. 分档审核（提交前必经）

| 档 | 范围 | 处理 |
|---|---|---|
| 低 | 纯前端样式/文案/注释/文档 | 免审 |
| 中 | 后端接口/报表/一般逻辑 | 审摘要 + diff + 待验证点 |
| 高 | 财务内核/守恒对账/迁移/修数脚本/派奖写路径 | 审方案 + diff + 测试 + 不变量清单 |

审核必看四条：① 不变量对称性（forward/reverse 两边都改了）；② 边界枚举（休息/平移/减半/回退/爆单/待定 组合不漏）；③ 测试钉死（红→绿、断言真能抓住原 bug）；④ 改数纪律（dry-run → 人工 review → apply）。

提交前有第二双眼睛审；中/高档未过审不得提交。

## 5. 版本同步（集成收口时）

提交前每处都改：后端版本常量（带前缀如有）、前端包版本（lockfile 两处）、变更日志。patch 位别贪多；minor/major 进位先问人。

## 6. 测试与生产数据护栏

- 全量测试串行跑（单库）防跨文件污染。
- 前端改动另跑 lint + 构建。
- 永不碰生产 env 文件。
- 生产数据默认保留；破坏性/清库/修数操作一律 dry-run → review → apply。
- 种子脚本只碰指定的 demo 租户，绝不碰真实租户。

## 7. 定义不改口

财务定义固化在权威文档。发现实现偏离时，以用户最新口径为准，文档 + 代码 + 记忆三处同步修正，不反复确认。

## 标准收口顺序

1. 定档；高的话先摸影响面（检查器镜像点、守恒恒等式、边界）。
2. 改代码 + 镜像检查器 + 补测试（红→绿）。
3. lint + 全量串行测试。
4. 高档 → 送审 → 过审才继续。
5. 版本处处同步（进位先问人）。
6. 提交 + push（自动触发部署）。
